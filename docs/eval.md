# Evaluation Framework

This document outlines the strategy for evaluating the performance, accuracy, and quality of the itineraries generated by the Dubai AI Travel Planner. Because LLM outputs are non-deterministic, we require structured evaluation pipelines.

## 1. Evaluation Criteria

Itineraries will be evaluated across the following core dimensions:

1. **Constraint Adherence (Pass/Fail):**
   - Does the total estimated cost stay strictly within the `budget_usd`?
   - Does the duration match `duration_days`?
   - Are `avoidances` strictly excluded (e.g., no meat for vegetarians)?
2. **Formatting & Schema (Pass/Fail):**
   - Does the API return a 100% valid `PlanResponse` Pydantic model without triggering 500 errors?
3. **Quality & Realism (Score 1-5):**
   - *Feasibility:* Is the daily schedule physically possible (e.g., factoring in travel time between Dubai Marina and Deira)?
   - *Accuracy:* Do the prices reflect realistic Dubai estimates? (e.g., A Burj Khalifa ticket shouldn't cost $5).
4. **Personalization (Score 1-5):**
   - How well are the user's `preferences` integrated into the itinerary?

## 2. Evaluation Datasets

A golden dataset of test prompts should be maintained for evaluation. Examples:

* **The Backpacker (Low Budget):** "Plan a 5-day trip to Dubai for 1 person with a strict $500 budget. Avoid expensive restaurants, prioritize public transit."
* **The Luxury Couple (High Budget):** "Plan a 3-day honeymoon in Dubai for 2 people with a $10,000 budget. Must include fine dining, a desert safari, and a 5-star hotel."
* **The Family Trip (Logistics Heavy):** "Plan a 4-day trip to Dubai for a family of 4 (2 adults, 2 young kids). Need kid-friendly activities, avoid extreme sports, budget $3000."
* **The Impossible Trip (Edge Case):** "Plan a 14-day trip to Dubai for $200."

## 3. Evaluation Methodologies

### 3.1 LLM-as-a-Judge (Automated Evals)
We will use a superior model (e.g., GPT-4o or Gemini 1.5 Pro) to automatically score the outputs of our graph based on a predefined rubric. 

**Process:**
1. The `evals.py` script runs the Golden Dataset prompts through the FastAPI endpoint.
2. The outputs are passed to the Judge LLM along with the original prompt.
3. The Judge LLM outputs a JSON structured evaluation:
   ```json
   {
     "budget_adherence": true,
     "realism_score": 4,
     "personalization_score": 5,
     "feedback": "Great itinerary, but slightly underestimated the cost of taxi fare between downtown and the Palm."
   }
   ```

### 3.2 LangSmith Integration
We will integrate LangSmith to track and monitor agent traces.
- Monitor token usage and latency per node (Destination vs Logistics vs Budget).
- Capture error rates for Pydantic parsing failures.
- Allow human reviewers to manually annotate and score traces within the LangSmith UI.

### 3.3 Unit & Integration Testing
- Continue using `pytest` to enforce deterministic behavior (e.g., the graph retries exactly 2 times on review failure).

## 4. Roadmap for Evals implementation
1. Create `tests/evals.py` to iterate over a JSON file containing the Golden Dataset.
2. Implement the LLM-as-a-Judge prompt.
3. Integrate LangSmith environment variables (`LANGCHAIN_API_KEY`, `LANGCHAIN_TRACING_V2=true`).
4. Set a CI/CD pipeline to run automated evals on PRs before merging.
